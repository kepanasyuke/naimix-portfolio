Архитектура и границы сервисов

Сервисы общаются только по HTTP-контрактам, у каждого своя схема данных. Решения зафиксированы в ADR.

Клиент / фронтенд-портфолио
↓ REST, JSON
auth-service · 8081 — выдача и отзыв токенов
vacancy-service · 8082 — домен вакансий и кэш
matching-service · 8083 — TF-IDF и ранжирование
notification-service · 8084 — идемпотентная доставка
billing-service · 8085 — холды и блокировки
analytics-service · 8086 — счётчики и JVM
ai-assistant-service · 8087 — генерация текста

Ключевые решения (ADR)

  • JWT выпускаются и проверяются через Spring Security Nimbus, отзыв — отдельным валидатором
  • H2 в режиме PostgreSQL для локального запуска, PostgreSQL — в compose и Kubernetes
  • Кэш и счётчики за интерфейсом: память по умолчанию, Redis через профиль
  • ИИ-фичи без внешних ключей: детерминированные движки, провайдер заменяем

Полные тексты — в docs/adr, диаграммы C4 — в docs/c4.

Код-стайл, который проверяет сборка

Правила не декларация, а падающий билд: Checkstyle подключён к фазе verify во всех модулях.

  • 1Одна точка выхода. ReturnCount = 1, для void — 0 возвратов.
  • 2Функция в один-два оператора. ExecutableStatementCount ≤ 2 для методов.
  • 3Без continue, break, while и do. Запрещены на уровне токенов.
  • 4Сложность ≤ 3, вложенность условий ≤ 1.
  • 5Javadoc на публичных методах, без звёздочных импортов, длина строки ≤ 120.

config/checkstyle/checkstyle.xml

<module name="ReturnCount">
  <property name="max" value="1"/>
  <property name="maxForVoid" value="0"/>
</module>

<module name="IllegalToken">
  <property name="tokens"
            value="LITERAL_BREAK,LITERAL_CONTINUE,
                   LITERAL_WHILE,LITERAL_DO"/>
</module>

<module name="ExecutableStatementCount">
  <property name="max" value="2"/>
</module>
