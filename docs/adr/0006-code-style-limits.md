# ADR 0006. Жёсткий лимит операторов в функции и одна точка выхода

**Статус:** принято (с оговорками)
**Дата:** 2026-11-08

## Контекст

Требование заказчика: одна точка выхода из функции, функции в один-два оператора, запрет
`continue`, `break`, `while`. Правила должны проверяться сборкой, а не соблюдаться на словах.

## Решение

`config/checkstyle/checkstyle.xml` подключён к фазе `verify` во всех модулях:

- `ReturnCount max=1`, `maxForVoid=0` — ровно один `return`, в void-методах возвратов нет;
- `ExecutableStatementCount max=2` для `METHOD_DEF`;
- `IllegalToken` для `LITERAL_BREAK`, `LITERAL_CONTINUE`, `LITERAL_WHILE`, `LITERAL_DO`;
- `CyclomaticComplexity max=3`, `NestedIfDepth max=1`, `MethodLength max=8`.

Аналогичный режим для фронтенда задан в `web/eslint.config.mjs`: `max-statements: 2`,
`complexity: 3` и `no-restricted-syntax` на `while`/`do-while`/`break`/`continue`.

## Последствия

- Плюс: функции действительно маленькие, ветвление плоское, побочные эффекты локальны.
- Плюс: `try/catch` с двумя возвратами становится невозможен — ошибки либо пробрасываются,
  либо обрабатываются фреймворком (см. ADR 0002).
- Минус: код становится фрагментированным — вместо одного метода на 12 строк появляется четыре
  по две. Читаемость спорна, навигация дороже.
- Минус: часть идиом Spring (например, настройка цепочки фильтров) разбивается на методы-обёртки,
  что выглядит непривычно для ревьюера.
- Минус: лимит в два оператора заставляет выносить даже проверки в отдельные `guard`-методы.

## Альтернативы

- Мягкий вариант (`max=4`, javadoc по желанию) — привычнее, но не выполняет условие заказчика.
- Только линтер в IDE без сборки — правила перестают быть обязательными.
