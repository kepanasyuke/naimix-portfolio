# ADR 0001. Монорепозиторий из семи независимых сервисов

**Статус:** принято
**Дата:** 2026-11-08

## Контекст

Портфолио должно показать разные классы backend-задач: безопасность, доменную модель, асинхронность,
деньги, наблюдаемость и ИИ-фичи. При этом проверять работу нужно локально, без кластера и внешних сервисов.

## Решение

Один Maven-реактор с семью самостоятельными Spring Boot приложениями. Каждый модуль имеет собственный
`pom.xml`, свой конфиг и порт (8081–8087). Общих библиотек нет: дублирование небольших DTO дешевле
связанности, а контракты остаются явными.

## Последствия

- Плюс: одна команда `mvn verify` проверяет все сервисы; границы модулей видны сразу.
- Плюс: любой сервис запускается и собирается в Docker отдельно.
- Минус: часть кода повторяется (формат ошибок, обработчики валидации).
- Минус: при росте числа модулей время сборки растёт линейно.

## Альтернативы

- Отдельные репозитории на каждый сервис — сложнее поддерживать и проверять в рамках портфолио.
- Один монолит с пакетами — не демонстрирует распределённое взаимодействие и разные хранилища.
