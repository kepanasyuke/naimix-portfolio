# ADR 0003. H2 в режиме PostgreSQL для локального запуска

**Статус:** принято
**Дата:** 2026-11-08

## Контекст

Сервисы должны запускаться на машине разработчика без Docker и без установленного PostgreSQL.
Готовые скачиваемые бинарники PostgreSQL в этом окружении недоступны, а установка требует прав администратора.

## Решение

Профиль по умолчанию использует H2 в режиме совместимости `MODE=PostgreSQL`, с инициализацией схемы
через Hibernate. Реальный PostgreSQL включается переменными `DB_URL`, `DB_USER`, `DB_PASSWORD`
и присутствует в `infra/docker-compose.yml` и манифестах Kubernetes.

## Последствия

- Плюс: `mvn spring-boot:run` работает сразу, тесты не требуют внешней инфраструктуры.
- Минус: H2 не воспроизводит поведение блокировок и планировщика PostgreSQL, поэтому
  сценарии конкурентности (например, `PESSIMISTIC_WRITE` в биллинге) нужно проверять на реальной базе.
- Минус: `ddl-auto=update` недопустим в production — там нужны миграции (Flyway/Liquibase).

## Альтернативы

- Testcontainers — точнее, но требует Docker на машине сборки.
- Встроенный PostgreSQL-эмулятор — тяжёлая зависимость и неполное покрытие диалекта.
