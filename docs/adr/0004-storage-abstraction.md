# ADR 0004. Кэш и счётчики за интерфейсом

**Статус:** принято
**Дата:** 2026-11-08

## Контекст

Redis нужен для кэша вакансий, списка отозванных токенов и счётчиков аналитики. Но для демонстрации
и тестов окружение не должно требовать запущенного Redis.

## Решение

Каждая инфраструктурная возможность спрятана за интерфейсом (`TokenStore`, `CounterStore`,
`CacheManager`), а реализация выбирается свойством:

- `auth.token-store=redis|memory`
- `analytics.store=redis|memory`
- `spring.cache.type=redis|simple`

По умолчанию включены in-memory реализации, Redis — через профиль или переменную окружения.

## Последствия

- Плюс: сервис стартует без внешних зависимостей, тесты быстрые и детерминированные.
- Плюс: переход на Redis не требует изменений в доменном коде.
- Минус: in-memory вариант не переживает рестарт и не разделяется между репликами — в Kubernetes
  обязательно включать Redis-реализации (это прописано в ConfigMap).

## Альтернативы

- Жёсткая зависимость от Redis — ломает локальный запуск и усложняет CI.
- Абстракция Spring Cache для всего — не покрывает уникальные операции вроде отзыва по `jti`.
